# LuoBackup

BungeeCord 代理插件，直接读取代理能够访问的子服目录，无需在 Spigot 子服安装插件。需要 Java 8 或更高版本，以及与子服共享文件系统的 BungeeCord；不能只通过 BungeeCord 的服务器地址备份远程机器。

## 安装

将 `LuoBackup.jar` 放入代理的 `plugins` 目录，启动一次代理生成 `plugins/LuoBackup/config.yml`，修改配置并重启代理。配置相对路径以代理进程的工作目录为准，而非配置文件所在目录。默认配置适用于本工作区的 `proxy` 工作目录与 `server/survival`。首次启动且没有已有备份时会在约 10 秒后开始备份；此后约每分钟检查一次。默认仅启用 survival，首次运行就会复制数据，请先确认路径和磁盘空间。

添加子服时，在 `servers` 下复制 survival 配置块并修改名称和 `directory`；名称只允许英文字母、数字、下划线和短横线。每个子服单独设置：

- `enabled`：是否启用。
- `directory`：子服根目录，必须包含 `server.properties`。
- `interval-hours`：现实时间间隔，整数小时；从最近完成的 ZIP 修改时间计算，停机时间也计入。重启后已到期会立即开始，时钟变化会影响计划。
- `slots`：最多保留的 ZIP 数量，至少 1。
- `max-size-bytes`：该子服所有备份 ZIP 的总容量上限，0 为无限制。例如 10737418240 代表 10 GiB。
- `full`：`stop` 停止新备份；`delete-oldest` 在新备份完成后删除最旧 ZIP。单个新 ZIP 超出大小上限时保留所有旧备份并报错。生成 ZIP 时需要额外的临时磁盘空间，容量上限不包括临时文件；删除失败时可能暂时超过限额。
- `world`、`nether`、`end`：世界目录名，默认分别为 `world`、`world_nether`、`world_the_end`，必须是三个不同的单层目录名。
- `include.world`、`include.nether`、`include.end`：分别备份三个世界目录。
- `include.player-data`：包含三个世界目录中的 `playerdata`、`stats` 和 `advancements`。关闭时从已选世界排除这些目录；开启时即使对应世界未选中也会包含这些目录（如果存在）。
- `include.plugins`：备份子服整个 `plugins` 目录，包括插件 jar、配置和存放在其中的数据。

默认全选上述五项、72 小时、3 个槽位、无限容量、满槽删除最旧备份。此处“全量”指全选上述五类；不包括 `server.properties`、服务端 jar 或子服根目录中的白名单等其他文件。已选世界或插件目录不存在时该次备份失败，不会删除旧备份。数据库和插件目录外的数据不在备份范围内。ZIP 输出在 `backup-directory/<子服名称>/`。插件只管理自身命名的 `backup-*.zip`，不要在该目录放置同名的其他文件。

## 手动备份和控制台日志

在 BungeeCord 控制台输入 `luobackup now survival`，或在游戏内输入 `/luobackup now survival`。游戏内需要代理权限 `luobackup.manual`；子服名称必须存在于配置的 `servers` 中。手动备份会全选主世界、下界、末地、玩家数据和插件目录，无视启用开关、内容选择、定时间隔、槽位数、容量上限和满槽策略；子服路径、世界目录名和备份根目录仍用于定位文件。所需世界或插件目录不存在时会报错。

手动 ZIP 存放在 `backup-directory/<子服名称>/manual/`，不会计入自动备份的槽位、容量和间隔，也不会被自动轮换删除，需要自行清理。为避免同时写入多个备份，已有备份执行时会拒绝新手动请求，请稍后重试。

控制台会输出备份请求、数据来源与目标、自动备份槽位和容量、选中目录、每 1000 个文件的进度、删除旧备份、完成文件数和用时，以及失败原因。启动日志还会显示已配置子服和手动命令。

## 一致性和恢复

此插件在代理端直接读取文件，不调用 Spigot API 或通知子服保存：在线游戏期间备份可能混入尚未落盘或正在写入的数据，插件数据库也可能不一致。世界根目录的 `session.lock` 是运行时锁文件，会自动排除；其他无法读取的文件会使备份失败并输出文件路径。关键备份建议先停止子服，等待文件完全写入，再执行到期备份；代理和存储必须保持运行。恢复时先停止对应子服，将 ZIP 内所需目录解压覆盖至子服根目录，先另存现有数据，并检查世界和插件版本兼容性。请定期将备份复制到独立存储并测试恢复。

## Windows 和 Linux

同一个 JAR 可用于 Windows 和 Linux。配置路径按代理启动时的工作目录解析：例如代理工作目录为 `/srv/mcserver/proxy`、子服为 `/srv/mcserver/server/survival` 时，可使用 `../server/survival`，也可以填写 Linux 绝对路径 `/srv/mcserver/server/survival`。从 Windows 迁移配置时，请修改所有 Windows 盘符和反斜杠路径。确保代理运行账户对选中的子服数据有读取权限、对备份目录有创建和写入权限，并且两个进程能访问同一文件系统。插件不跟随符号链接；遇到符号链接会报错。数据库文件可能被锁定或在备份时变化，需要使用对应数据库的备份方法。

世界的 `session.lock` 会在两个平台上排除；这不保证其他插件或数据库文件能在线读取，也不保证运行中数据的一致性。
